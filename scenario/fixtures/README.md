# Recorded runs — RD-2 HX-5

The JSON event log of every window, order, settlement and mirror snapshot a run
produced, in the **frozen** `indexer/schema/` (IX-2). This is Phase 5's offline
replay input (FE-10): the frontend plays these back with no infrastructure
behind it, and it must not be able to tell the replay from a live run (IX-1,
TS-5).

| File | What it covers |
|---|---|
| `run.json` | A whole session: a settled window, a window whose orders rolled, a poison eviction, a `postBatch`-skip rollback, and the repaired settlement after it. |
| `settled.json` | A.6's happy path — eight orders from eight accounts, one cross-layer transaction, `fills_per_settlement == 8`. |
| `rolled.json` | Mid-window drift beyond some limits: the orders inside their limit fill, the rest stay open and roll. |
| `evicted.json` | Poison eviction. No L1 receipt, no gas, every order open and intact. |
| `rolled-back.json` | The `postBatch` skip: the batch landed without the entry, so the fills are undone **and the L1 gas was spent**. |
| `*.observations.jsonl` | The raw observations each run was folded from — one JSON fact per line. |

## Provenance

The files on disk are generated by the **settlement oracle**
(`scenario/lib/fixture.ts` → `scenario/lib/simulate.ts`), not by an enclave:
the amounts are what `WindowBook` and `SettlementRouter` would produce for
those inputs, computed by `scenario/lib/book.ts`, and the clock is pinned so a
diff on a fixture is a real change rather than today's date.

`scenario/dex-scenario.sh --record` regenerates them from a **real enclave
run**: it writes the observation log the enclave produced and folds it with the
same recorder (`scenario/lib/record.ts`). Both paths produce byte-identical
shapes, because both go through one recorder and one validator; only the
numbers differ.

Regenerate the committed set with:

```bash
node scenario/lib/cli.ts fixtures scenario/fixtures
```

`scenario/lib/record.test.ts` fails if the committed `run.json` and a fresh
fold of the observation log disagree, so a stale fixture cannot survive
`scenario/dex-scenario.sh --self-test`, which CI runs on every pull request.

## Validating one

```bash
node scenario/lib/cli.ts validate scenario/fixtures/run.json
```

The validator checks the fixture against the frozen schema's own exported
constants — the state lists, the A.4 transition tables, the A.5 metric names
and `SCHEMA_VERSION` — never against a list transcribed into the scenario. If
the fixture and the schema disagree, **the schema wins** and the fixture is
wrong.
